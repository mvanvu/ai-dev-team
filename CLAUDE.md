# CLAUDE.md

This repository is the source of the `ai-dev-team` Claude Code plugin (marketplace `mvanvu`): 3 agents in `agents/` (developer, reviewer, qc), skills in `skills/`, orchestrator `skills/dev-team/` (the leader also profiles and plans). See README.md.

## Working on the plugin

- All files are written in English; replies to the user are in Vietnamese.
- Before acting on a change request (new rule, new agent, restructure, proposal from elsewhere), first reply with the pros and cons, what the plugin already covers, and a recommendation (or alternatives) — then wait for the user's decision. Only fixes the user explicitly ordered ("sửa luôn", "làm đi") skip this step.
- Agents and skills are namespaced as `ai-dev-team:<name>` at runtime. When adding a new agent or skill, reference it with the prefix wherever it is invoked (`subagent_type`, workflow `agentType`, "Follow the `ai-dev-team:<skill>` skill").
- New agent → also update the team table, routing and build loop in `skills/dev-team/SKILL.md`, the README agent table, and the change log below.
- The plugin never installs anything: no hooks, no dependencies on other plugins. Third-party skills (`superpowers`, `ui-ux-pro-max`) are only referred to with "when it is installed". Material adapted from third-party work keeps its notice in `THIRD-PARTY-NOTICES.md`.
- New or changed rule → put it in one reference file as a numbered check, register the pack in `skills/dev-team/references/rule-packs.md` (ID, applies-when, must-read, verifier), and point to it from other files instead of restating it. Renumbering checks changes rule IDs — append new checks at the end.
- Never name the projects the plugin was used in, or their specific tools, targets or file names, anywhere in the plugin — rules, examples, scripts and change log rows included. Describe what happened in generic terms ("a real run", "a parallel task", "the whole e2e target").
- After any change run `python3 scripts/check-plugin.py` (cross-references, rule packs, version vs change log), `claude plugin validate .` and `claude --plugin-dir . plugin details ai-dev-team`.
- Versioning: bump the version in `.claude-plugin/plugin.json` only once per push, right before pushing — not per change and not per commit. All commits pushed together share one version: if the working version is already ahead of the last pushed one, keep it and add to the same change log row. Bump only the patch number — 1.0.0 → 1.0.1 → 1.0.2 → … Do not bump minor/major unless the user asks. Record the version in the change log row.
